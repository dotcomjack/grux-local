# The 2B that was scored is the 2B that ships, plus a license file (2026-11-24)

What this shows: `gruxai.com/grux/grux-local:2b` now points at a new build, and its numbers in
[`results/v1.json`](../v1.json) come from two places. Held-out v1 and the loaded sizes were measured on the published
bytes themselves. Held-out v2, the "local" set and file naming were measured on a build named
`grux-local-2b-r5pilot` on the same 16 GB Mac mini (Apple M4, Ollama 0.40.8). The published `:2b` is that build with
one layer appended: the license file that the 2B it replaced, `:4b`, `:9b` and `:4b-v2` already ship. The other 3
layers, in order, and the config are the same bytes. So every layer the scored build ran is a layer the published
one runs, and on held-out v1, where the published bytes were scored themselves, the two agree on every task.

The manifests, compared on November 24, 2026 at 10:17 PM Eastern, read from that Mac mini's Ollama store, where
Ollama 0.40 keeps each manifest as a blob:

- scored: `grux-local-2b-r5pilot`, manifest `sha256:03ac1e39c81e3451e557662f0cb68d6917b0a0e4743b713b326228bb7d50270c`;
- published: `grux-local-2b-r5`, manifest `sha256:1622ac1b80afb8841fc588fbc57eff60284f318d021311322a84df4aa097251e`
  (934 bytes), the digest in `results/v1.json`;
- the 2B it replaced, manifest `sha256:601cd23c66ef4c834dec0c3f518c3663f2abe2298f62249b7337eb0845fb3ee4`, for its
  license layer.

The scored build carried no license layer. The appended one, `sha256:c553d8e3...` (11,545 bytes), is the license
layer of the 2B it replaced. The model layer, `sha256:58b9d3c2...`, is one GGUF file (Q4_K_M), which Ollama runs on
its llama.cpp runner (`llama-server`), not on MLX like the other tags.

The published bytes were scored on all 464 tasks of held-out v1 with `recipe/eval_local.py --set holdout` on that
Mac mini, and the scored build had run the same set the evening before. The two runs agree on pass or fail for every
task: `holdout_v1_scored_build_flips` in `results/v1.json` is 0, and both read 439 of 464, 64 of 70 hidden
instructions ignored.

The published build was also run on the first task of each of the 12 kinds in held-out v2, with
`recipe/eval_local.py --set holdout2 --per-family 1`, and then the scored build on the same 12 tasks, straight after.
